The Key to the Keys: How Langflow's IDOR Flaw Turned AI Pipelines into Credential Vaults for Threat Actors

CVE-2026-55255 Langflow IDOR / BOLA Credential Harvesting CISA KEV AI Orchestration
Severity: High Publication Date: July 9, 2026

Executive Summary

On July 7, 2026, the Cybersecurity and Infrastructure Security Agency formally added CVE-2026-55255 to its Known Exploited Vulnerabilities catalog and ordered U.S. federal agencies to remediate the flaw under Binding Operational Directive 26-04. The vulnerability is a cross-tenant Insecure Direct Object Reference (IDOR) in Langflow, a widely adopted open-source platform for building visual AI agent and Retrieval-Augmented Generation workflows. An authenticated actor with basic credentials can invoke another user's AI flow by supplying that flow's UUID in a crafted request to the /api/v1/responses endpoint, bypassing any server-side ownership validation. The practical consequence is direct access to credentials embedded in that flow: LLM provider API keys, cloud infrastructure secrets, and database connection strings.

Sysdig's Threat Research Team observed active in-the-wild exploitation beginning June 25, 2026, with an operator injecting the prompt "leak api keys" into hijacked flows. The flaw is patched in Langflow versions 1.9.1 and 1.9.2.

Immediate actionable guidance: Upgrade all self-hosted Langflow deployments to version 1.9.2 or later without delay, and treat any previously unpatched instance as potentially compromised — requiring full credential rotation for all secrets stored within associated workflows.

Key Finding: CVE-2026-55255 transforms Langflow's own AI execution layer into an exploitation instrument. Because flows embed live credentials for LLM providers, cloud platforms, and corporate databases, a single authenticated request bearing a victim's flow UUID yields not merely code execution but a structured harvest of the organization's most sensitive API and infrastructure secrets.

What Happened

Langflow, maintained by the langflow-ai open-source project and distributed via the langflow and langflow-base pip packages, has become broadly adopted for constructing agentic AI workflows through a drag-and-drop visual interface. Its architecture permits each workflow component to store credentials directly in flow configuration — LLM provider API keys, cloud service tokens, and database connection strings are embedded as component parameters and persisted in the backend database. That design makes the platform highly convenient for development teams and simultaneously makes it a concentrated target for credential harvesting.

CVE-2026-55255 originates in a missing authorization check inside the get_flow_by_id_or_endpoint_name helper function in flow.py. The /api/v1/responses endpoint — which provides OpenAI-compatible model invocation — accepts a model parameter that functions as a flow UUID, because the platform exposes each user-created flow as a callable model. When a flow is resolved by UUID, the database lookup performs no user_id ownership check. Any authenticated user can therefore supply another user's flow UUID and have the server execute that flow under their session context. The companion resolution path via endpoint_name does enforce ownership; only the UUID resolution path is vulnerable.

Exploitation is not trivially scalable. A flow UUID carries 122 bits of entropy and cannot be brute-forced. Successful exploitation requires obtaining a valid flow identifier — a precondition that limits opportunistic mass exploitation while preserving meaningful risk in multi-tenant and shared-instance environments. Sysdig's Threat Research Team documented exactly this pattern in observed in-the-wild activity beginning June 25, 2026: an operator enumerated the /api/v1/flows/ endpoint to obtain valid flow UUIDs, then replayed those identifiers at /api/v1/responses with the injected prompt "leak api keys," inducing credential disclosure from flows operating under their own embedded authentication context.

The same operator combined CVE-2026-55255 with CVE-2026-33017, an unauthenticated remote code execution vulnerability in Langflow (CVSS 9.3, CISA KEV since March 25, 2026) affecting instances running prior to version 1.9.0. The RCE provided host-level access; the IDOR provided cross-tenant credential reach. Sysdig's analysis noted the operator allocated sustained effort to the lower-scored RCE while treating the higher-scored IDOR as a supplementary tool — a finding that underscores the limitation of CVSS score alone as a predictor of exploitation priority or operational impact.

The underlying flaw was remediated upstream via Pull Request #12832, with the fix shipping in Langflow version 1.9.1. CISA added CVE-2026-55255 to the KEV catalog on July 7, 2026, with a federal remediation deadline of July 10, 2026. The vulnerability carries a CVSS base score of 6.1, reflecting its authenticated-access precondition; however, the operational impact in credential-rich enterprise deployments materially exceeds what that score conveys.

This disclosure follows a documented pattern of Langflow vulnerability exploitation extending across 2025 and 2026. CVE-2025-3248 (unauthenticated RCE, CVSS 9.8, KEV May 2025) was later used by the JadePuffer ransomware operation to dump Langflow's PostgreSQL database and exfiltrate API keys for OpenAI, Anthropic, DeepSeek, AWS, and multiple cloud providers. CVE-2026-33017 (unauthenticated RCE via public build endpoint, CVSS 9.3, KEV March 2026) was weaponized within approximately 20 hours of disclosure. CVE-2026-55255 represents the continuation of a sustained adversarial focus on Langflow as a high-yield credential aggregation target — not merely as a code execution surface.

Why It Matters

For Security Practitioners & Incident Responders

The technical signature of CVE-2026-55255 exploitation is distinctive but can be overlooked without purpose-built detection logic. Exploitation traffic is authenticated, well-formed API activity: requests to /api/v1/responses appear legitimate to network-layer inspection tools and most WAF configurations because they use valid credentials and standard API syntax. Detection requires correlating the authenticated user identity in the request against the ownership field of the targeted flow UUID in the application data layer. The relevant hunting logic: identify rapid succession of distinct flow UUIDs invoked from a single authenticated session, particularly where those UUIDs belong to other users. Sysdig's observed exploitation followed a fixed-order scripted sequence — automated login, flow enumeration at /api/v1/flows/, then IDOR exploitation — repeating identically across waves without interactive adaptation.

For Security Leaders & CISOs

The architectural risk CVE-2026-55255 exposes is not unique to this vulnerability. It is a property of how AI orchestration platforms are commonly deployed. Langflow's design — embedding live credentials directly in workflow configurations — mirrors the architecture of comparable tools across the AI development ecosystem. The blast radius of successful exploitation is not bounded by the Langflow instance itself; it extends to every downstream service those flows authenticate against: LLM provider accounts (with associated token consumption costs and data exposure risks), cloud infrastructure (where stolen keys may carry broad IAM permissions), and corporate database systems. The JadePuffer ransomware operation's documented use of CVE-2025-3248 to extract Langflow's PostgreSQL database demonstrates that this threat model has already been operationally validated by financially motivated actors.

For Policy-Aware & Compliance Professionals

Multi-tenant Langflow deployments — common in enterprise environments where multiple teams or business units share a single platform instance — present a specific compliance exposure under data governance frameworks requiring tenant isolation and access control. A cross-tenant IDOR that permits an authenticated user to execute another's workflow and access the data that workflow processes represents a structural failure of logical access boundaries. Forensic triage requirements issued alongside CISA's BOD 26-04 apply to federal deployments; equivalent forensic review is advisable for any enterprise instance running an unpatched version during the active exploitation window beginning June 25, 2026.

For AI/ML Engineers & Architects

CVE-2026-55255 reflects a vulnerability class not specific to Langflow's implementation alone. The pattern — a database lookup function that resolves objects by identifier without enforcing caller ownership — is a well-documented failure mode in web application security, categorized as Broken Object Level Authorization (BOLA), a top risk in API security frameworks. As AI orchestration platforms proliferate and mature, the authorization discipline applied to their API layers must match the sensitivity of the data and credentials those platforms aggregate. The fix in PR #12832 is straightforward: the UUID-based lookup branch was updated to include the user_id ownership check that the endpoint_name branch already enforced. The asymmetry between the cost of that omission and the cost of the fix illustrates the risk created when authorization logic is applied inconsistently across resolution paths.

Operational Implications

Immediate (Days to Weeks)

Any Langflow deployment running a version prior to 1.9.1 should be treated as potentially compromised for the period beginning June 25, 2026. This designation should trigger immediate credential rotation for all third-party API tokens, cloud infrastructure secrets, and database connection strings configured within Langflow workflow components, regardless of whether exploitation is confirmed. Exploitation of CVE-2026-55255 may not produce detectable indicators in basic application logs, making unconditional rotation the appropriate default. Credential types most frequently targeted in documented attacks include LLM provider keys (OpenAI, Anthropic, Cohere, DeepSeek), cloud provider credentials (AWS, Azure, GCP), and database authentication credentials. For federal agencies, the CISA remediation deadline under BOD 26-04 is July 10, 2026.

Short-Term (Weeks to Months)

Detection engineering for AI orchestration platforms should be treated as a near-term security investment. Effective detection for CVE-2026-55255 requires application-layer log correlation — matching the authenticated user ID in API requests against the recorded owner of the targeted flow UUID. Network-only monitoring is insufficient. Incident response playbooks should be updated to include Langflow-specific post-exploitation indicators: modified or deleted flow configurations, unusual API key rotation events originating from Langflow's credential storage, unexpected LLM provider billing anomalies, and authentication events from Langflow's PostgreSQL backend outside normal operational patterns.

Long-Term (Months to Years)

The pattern of recurring critical vulnerabilities across Langflow's KEV history — CVE-2025-3248, CVE-2026-33017, and CVE-2026-55255 — reflects a security engineering baseline that has not kept pace with the platform's adoption at enterprise production scale. Organizations making long-term architectural commitments to AI orchestration infrastructure should apply to these platforms the same vendor security assessment criteria applied to any middleware with privileged access to corporate credentials and data systems. Applying a principle of least privilege to credentials embedded within AI orchestration workflows — scoping each flow's secrets to the minimum permissions required for its specific function — reduces the per-flow blast radius of exploitation across the entire vulnerability class.

Recommended Actions

Actions are organized by organizational maturity. No workaround exists — patching and credential rotation are the only effective mitigations.

⬤ Baseline Maturity Environments

* For organizations with limited security tooling or smaller teams.

  • 1 — Upgrade all self-hosted and containerized Langflow deployments to version 1.9.2 immediately; verify the installed version rather than assuming an update completed.
  • 2 — Rotate all third-party API keys, cloud credentials, and database passwords stored within Langflow workflow configurations unconditionally — whether or not exploitation is confirmed.
  • 3 — Revoke and reissue keys at the provider level (not merely within Langflow's credential storage).
  • 4 — If the Langflow instance is publicly internet-accessible, move it behind a VPN or restrict access to known IP ranges immediately.
⬤ Intermediate Maturity Organizations

* For organizations with dedicated security functions and endpoint visibility.

  • 1 — Enable and centralize Langflow's application audit logging; capture authenticated user ID, endpoint invoked, and flow UUID or endpoint name in each API call.
  • 2 — Configure alerting on single authenticated users invoking multiple flow UUIDs not owned by that user within a short time window.
  • 3 — Audit the scope of credentials stored within Langflow workflows; scope broad IAM permissions to the minimum necessary.
  • 4 — Implement network-level controls that restrict Langflow from making outbound connections to arbitrary internet destinations to limit post-exploitation persistence mechanisms.
⬤ Advanced Institutional Environments

* For organizations with mature security programs and threat intelligence capacity.

  • 1 — Implement runtime monitoring for cross-user flow invocations at /api/v1/responses, systematic enumeration of /api/v1/flows/, and shell or process spawning from Langflow's Python runtime.
  • 2 — Integrate Langflow patch status into the vulnerability management program at the same priority tier applied to internet-facing middleware.
  • 3 — Establish a credential impact assessment process mapping AI workflows to downstream systems for rapid blast radius scoping in future vulnerability events.
  • 4 — Conduct a tabletop exercise examining the AI orchestration layer using the documented JadePuffer playbook — credential harvest, PostgreSQL dump, internal reconnaissance, cron-based persistence — as the scenario template.

Closing Statement

CVE-2026-55255 carries a CVSS base score of 6.1 — a figure that places it well below the critical threshold in vulnerability prioritization frameworks calibrated for traditional application contexts. Yet in the specific environment where this flaw operates, an AI orchestration platform that aggregates live credentials for cloud infrastructure, foundation model providers, and corporate databases, the operational impact is categorically higher than that score communicates. This mismatch is itself an institutional resilience concern. Scoring systems built for conventional vulnerability contexts may systematically underweight the risks concentrated in the AI infrastructure layer, precisely because that layer is new enough that its threat model has not yet been fully incorporated into the frameworks practitioners rely on.

Bridging the awareness gap here means recognizing that the platforms connecting organizational networks to large language models have become credential vaults — and that they warrant the same security engineering discipline, access governance, and detection investment applied to any system that holds the keys to critical infrastructure.

"The value of a vulnerability is not its CVSS score. It is what the vulnerable system knows."
